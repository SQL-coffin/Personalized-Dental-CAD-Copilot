# CAD Copilot · 前端交互原型

版本：v0.2 原型（结构优先阶段）

> **这是交互原型，不是系统实现。**
>
> - 界面连接的 Runtime 在浏览器进程内运行。它的状态机、Policy Gate 和审批规则是真实代码，但 agent 是脚本，病例与几何是合成数据，没有连接任何 CAD 软件，没有调用任何模型，审批没有实际效力。
> - 完成本原型不代表 05 Agent Runtime 规范已经作为服务实现，也不代表任何研究假设得到验证。
>
> 「05」「06」指 `docs/05-agent-runtime-spec.md` v0.2 与 `docs/06-research-browser-mcp.md` v0.1，二者只在 PR #3 的分支上，`main` 上还没有。整体结构见[架构总览](../../docs/architecture/README.md)。

## 1. 位置与边界

```
apps/web/src/
  ui/          产品界面：只依赖 @cadcopilot/contracts
    presenters/  纯函数：状态文案、步骤显示、质量闸门复核、审批可用性
    components/  组件
    hooks.ts     订阅任务快照与事件、病例记录；提交状态；统一错误显示
  app/         组装层：选择 Runtime（模拟或 HTTP 占位）；原型控制面板（仅模拟部署）
  main.tsx     入口
```

- `ui/` 不知道 Runtime 是不是模拟的。任务状态一律来自 Runtime 的快照，界面不自行推导。
- `app/` 是唯一引用 `@cadcopilot/runtime` 与 `@cadcopilot/integrations` 的地方。
- 依赖方向由 `npm run check:boundaries` 强制（[ADR-0001](../../docs/architecture/adr/0001-workspace-modules.md)）。

UI 使用四个端口（`contracts/src/ports.ts`），刻意分开：

| 端口 | 用途 | 规范依据 |
|---|---|---|
| `RuntimeClient` | 部署信息、病例、任务快照、事件、创建任务、对话、取消、订阅 | 05 §5、§6 |
| `ApprovalChannel` | 批准、拒绝、要求修改。与对话完全分开，对话里的文字不可能经过这里 | 05 §10.3，I4 |
| `HumanFeedbackChannel` | 解除 BLOCKED 的人工回应，绑定任务与当前阻塞原因 | 05 §6.4，06 §3 |
| `RecordsClient` | 病例记录：负责牙技师、设计版本图、操作、几何差异、确认状态；数据层变更时通知 | 02，[ADR-0003](../../docs/architecture/adr/0003-one-technician-per-case.md)、[ADR-0005](../../docs/architecture/adr/0005-append-only-version-graph.md) |

## 2. 运行

在仓库根目录：

```bash
npm ci
npm run dev                                   # 开发服务器（模拟 Runtime）
VITE_RUNTIME_TRANSPORT=http npm run dev       # HTTP 占位：显示 NOT_IMPLEMENTED，不显示任何任务状态
npx vitest run --project @cadcopilot/web      # 本应用的测试
npm run check                                 # 模块边界 + 类型检查 + 全部测试
npm run build                                 # 生产构建到 apps/web/dist/
```

左下角的「原型控制 · 仅模拟」面板代表部署配置与模拟环境，不属于产品功能，只在模拟部署中出现。它可以：

- 切换运行模式；
- 选择下一个任务的场景；
- 调整模拟速度；
- 查看合成数据的生成假设。

## 3. 界面原则

1. **状态来自 Runtime**：「已批准」「已写入 CAD」「已取消」只在 Runtime 记录之后显示。提交后只显示「已提交」和回执，然后等待 Runtime 记录。
2. **能力驱动的控件**：没有对应端口或能力时不渲染控件。例如 assist 模式没有写入工具，就没有「批准」按钮。界面不显示无法执行的操作。
3. **模拟就标明是模拟**：
   - 页头显示「模拟部署」，以及还有几项集成没有接入真实系统；
   - 诊断面板逐项列出集成的实现状态（模拟 / 占位 / 已连接）和模型调用记录（脚本，未调用模型）；
   - 合成病例标「合成」。
4. **统一的错误显示**：所有层的错误都归一为 `ErrorInfo`，界面显示错误码，只对可重试的错误提供重试。

## 4. 已覆盖的交互

| 流程 | 界面 | 关键行为 |
|---|---|---|
| 主工作区 | 任务历史、新建任务（病例选择 + 自然语言描述 + 示例）、对话、后续消息 | 只列出分配给当前牙技师、尚未确认的病例，选项中显示当前版本。**不提供文件上传**：原始扫描需先经适配器去标识（04 §1.2）。离线研究模式不显示病例选择（06 §1） |
| 任务状态 | 状态徽标、阻塞提示、结束时的结果条 | 显示 05 §6.2 的全部任务状态。阻塞时给出原因、已完成的内容、需要谁做什么（05 §6.4）。结果条写明「未写入 CAD / 已写入 CAD / 写入结果不明」 |
| 计划与执行 | 执行计划时间线；被取代的旧计划可展开 | 显示 05 §6.5 的全部步骤状态。未执行的步骤显示为「未执行（任务已取消 / 计划已修订）」，不改写成别的状态 |
| 取消 | 「取消任务」→ 二次确认 →「取消请求已提交」→ 快照变为 CANCELLED 后才显示「已取消」 | 有写入正在进行时提示：取消不撤销已发生的写入 |
| 重新规划 | 审批时「要求修改方案」；证据缺失或需要人工反馈的阻塞时「改写计划」 | 只提供 Runtime 声明接受的回应（`BlockedReport.allowedResponses`） |
| 审阅与审批 | 候选卡片（展开图、偏好、质量闸门、区域表、来源与哈希、决策记录）+ 审批卡片 | 审批前展示候选哈希、基础版本、绑定范围、执行工具、闸门标准集、策略版本、有效期、一次性。批准需要二次确认 |
| 病例记录 | 「病例记录」面板，默认收起 | 负责牙技师与分配规则；设计版本图（从新到旧，每个版本的来源：AI 初始设计 S_0、牙技师编辑、撤销、Copilot 执行带审批与任务）；操作记录、几何差异、病例协变量；最终确认状态。数据层变更时自动刷新 |
| 工具执行与诊断 | 每个步骤的「详情」；「高级诊断」默认收起 | 工具 ID 与版本、权限级别、副作用、尝试次数与错误码、输入输出哈希、是否经过对账；预算、版本、集成与适配器、模型调用、事件日志与哈希链 |

加载、空状态、连接错误、HTTP 占位（不可重试）、任务加载错误、表单校验、操作提交失败，都有对应的界面状态。

## 5. 与规范的对应

| 规则 | 界面做法 |
|---|---|
| I4 审批只来自审批记录 | 审批走独立端口。对话输入框旁注明「对话消息不构成审批」；测试验证在对话里输入「我已批准」不改变任何状态 |
| I5 偏好与质量分开 | 两个并列的框分别展示，没有合并分数；注明偏好值不改变闸门结论 |
| I12 / §10.7 质量闸门失败即关闭 | 界面按逐项结果再复核一次：任何一项缺失、不可评价或未评价，都按未通过处理。Runtime 报「通过」但逐项结果不支持时，显示不一致警告并按未通过处理。未通过的候选只显示诊断与区域提示，不画候选几何，也没有审批入口 |
| 01 §5 规则 3 | AMBIGUOUS / UNMATCHED 区域只给区域提示，不画逐点位移 |
| §10.2 批准不等于放行 | 审批卡片与完成结果都写明「最终设计需要你在 CAD 中自行确认」 |
| §10.3 审批绑定基础版本 | 决定请求回传候选哈希与基础版本 ID。版本变化导致审批作废时，在步骤与审批记录中显示原因 |
| §7.3 结果不明先对账 | IN_DOUBT 显示为「结果不明」，任务被取消也不隐藏；只提供人工对账回应，没有「重试」按钮 |
| §9.2 叙述部分非权威 | 没有引用证据的 agent 消息标注「未引用证据」 |
| §4 运行模式由部署决定 | 模式只在页头显示，产品界面没有切换模式的控件（只在原型控制面板中） |
| §13 预算不能由模型修改 | 预算耗尽时不提供「追加预算」，只能取消 |
| 06 §3 访问挑战不自动求解 | 研究任务遇到 CAPTCHA 时暂停，只提供「继续」（人工在自己的浏览器中处理后）或「改写计划」 |
| 一病例一牙技师 | 只能为分配给自己的病例创建任务；病例记录写明「病例之间的差异不等于个人偏好」 |

## 6. 模拟场景

场景定义在 `packages/runtime/src/simulation/scenarios.ts`。一个场景是「故障计划 + 脚本 agent」，不编排状态；界面看到的状态是 Runtime 对注入故障的反应。

| 场景 | 模式 | 演示内容 |
|---|---|---|
| 标准流程 | assist-execute / assist | 通过闸门 → 等待审批 → 条件写入；assist 下只展示建议 |
| 偏好高，但未通过质量闸门 | assist-execute / assist | 表面贴合 P95 = 63 μm（模拟阈值 40 μm）。Policy Gate 拒绝以可采纳形式展示，只给诊断与区域提示 |
| 依据区域对应不明确 | assist-execute / assist | 远中颊侧 AMBIGUOUS，结论为「无法可靠判断」 |
| 只读工具超时后重试 | assist-execute / assist | FAILED_NO_EFFECT 后在 max_attempts 内重试 |
| 写入后回复丢失，结果不明 | assist-execute | IN_DOUBT → 自动对账无法判断 → 人工确认生效或未生效 |
| 审批期间设计被修改 | assist-execute | 执行前核对失败 → 审批作废 → 基于新版本重新生成并重新审批 |
| 证据校验失败 | assist-execute / assist | BLOCKED(missing_evidence)，必须写明说明才能改写计划 |
| 预算耗尽 | assist-execute / assist | BLOCKED(budget)，界面中只能取消 |
| 公开网页要求人工验证 | offline-research | BLOCKED(human_feedback)，可以继续或换来源 |

- shadow 模式不提供给牙技师的界面（建议不展示，05 §4），所以原型不模拟它。
- conflict 与 drift 两种阻塞原因由通用的阻塞提示处理，没有对应的模拟场景。

## 7. 接入真实 Runtime

接入时需要的后端接口（B1–B13）、HTTP 路由，以及当前界面有意不提供的功能，记录在[扩展点与未完成项](../../docs/architecture/extension-points.md)。

有意不提供的功能包括：

- E 级回滚；
- 追加预算；
- 冲突解决；
- assist 模式的采纳 / 拒绝反馈；
- 研究人员视图。

## 8. 已知限制

- Runtime 在浏览器进程内运行。任务描述不影响结果，结果由所选场景和合成数据决定。
- 没有三维视图。margin line 以「展开图」显示：横轴是 S_0 归一化弧长，纵轴是横向位移，数据是合成的。
- 没有持久化，刷新页面即清空任务与病例记录。
- 模拟身份未经认证。模拟部署中允许审批，但标明「审批无实际效力」；非模拟部署中，未认证身份不能审批，Runtime 和界面各检查一次。
- 界面文案为中文，没有引入国际化框架。
- 只做了基本的语义与键盘可达性（标题、区域标签、`aria-live`、焦点样式、非颜色的状态图形），没有经过屏幕阅读器的完整审查。
- 类型基于 05 v0.2（PR #3，未合并）。05 修订或合并后需要复核契约类型。
- 仓库没有 CI，测试和构建需要在本地运行。
