# CAD Copilot · 前端交互原型

版本：v0.1 原型

> **这是交互原型，不是系统实现。** Runtime 是脚本化的模拟适配器：回应与输入内容无关，病例与几何均为合成数据，没有连接任何 CAD 软件，审批没有实际效力。完成本原型不代表 05 Agent Runtime 规范的任何部分已经实现，也不代表任何研究假设得到验证。
>
> 文中的「05」「06」指 `docs/05-agent-runtime-spec.md` v0.2 与 `docs/06-research-browser-mcp.md` v0.1，二者目前只在 PR #3 的分支上，`main` 上还没有。

## 2. 实施方案

1. **契约先行**：在 `src/runtime/contract/` 中按 05 定义任务状态、步骤状态、阻塞报告、事件信封、候选、质量闸门、审批请求、错误等类型，以及三个端口（`RuntimeClient`、`ApprovalChannel`、`HumanFeedbackChannel`）。05 没有定义、但界面需要的结构标为「frontend proposal」。
2. **模拟适配器隔离**：`src/runtime/mock/` 按 05 §6.3 / §6.5 的转移表推进脚本化场景；出现规范不允许的转移就直接抛错，保证模拟本身不会示范非法状态。只有组装层 `src/app/` 引用它。
3. **产品界面只依赖契约**：`src/ui/` 不知道 Runtime 是不是模拟的；任务状态一律来自 Runtime 的快照，界面不自行推导。
4. **能力驱动的控件**：没有对应端口或能力时不渲染控件（例如 assist 模式没有审批通道，就没有「批准」按钮），不显示无法执行的操作。
5. **验证**：presenter 单元测试 + 模拟 Runtime 场景测试 + 整个 App 的交互测试；类型检查与生产构建；Playwright 截图检查桌面、移动端与深色模式。

技术选择：React 18 + TypeScript（strict）+ Vite 5 + Vitest。运行时依赖只有 `react` 与 `react-dom`；不引入 UI 组件库、状态管理库、路由或 CSS 框架。

## 3. 运行

```bash
cd frontend
npm ci
npm run dev         # 开发服务器
npm test            # 全部测试（vitest）
npm run typecheck   # tsc --noEmit
npm run build       # 类型检查 + 生产构建到 dist/
npm run preview     # 预览生产构建
```

左下角的「原型控制 · 仅模拟」面板可以切换模拟部署的运行模式、选择下一个任务的场景，以及调整模拟速度。这些控件代表部署配置与 Runtime 行为，不属于产品功能。

## 4. 目录与边界

```
src/
  runtime/contract/   UI ↔ Runtime 契约：只有类型与端口接口，没有逻辑
  runtime/mock/       模拟 Runtime（脚本场景、转移表、调度器）——仅原型使用
  ui/                 产品界面：只引用 runtime/contract
    presenters/       纯函数：状态文案、步骤显示、质量闸门复核、审批可用性
    components/       组件
    hooks.ts          订阅任务快照与事件；提交状态
  app/                组装层：创建模拟适配器，挂上原型控制面板
```

依赖方向：`app → ui → runtime/contract`，`app → runtime/mock → runtime/contract`。`ui/` 不引用 `runtime/mock/`。接入真实 Runtime 时，在 `app/` 中换成生产适配器（实现同样的三个端口），`ui/` 不需要改动。

三个端口刻意分开：

| 端口 | 用途 | 规范依据 |
|---|---|---|
| `RuntimeClient` | 部署信息、病例、任务快照、事件、创建任务、对话、取消、订阅 | 05 §5、§6 |
| `ApprovalChannel` | 批准 / 拒绝 / 要求修改；与对话完全分开，对话里的文字不可能经过这里 | 05 §10.3，I4 |
| `HumanFeedbackChannel` | 解除 BLOCKED 的人工回应，绑定任务与当前阻塞原因 | 05 §6.4，06 §3 |

## 5. 已覆盖的交互

| 流程 | 界面 | 关键行为 |
|---|---|---|
| 主工作区 | 任务历史、新建任务（病例选择 + 自然语言描述 + 示例）、对话、后续消息 | 病例只能从 Runtime 的假名化记录中选择；**不提供文件上传**（原始扫描需先经适配器去标识，04 §1.2）；离线研究模式不显示病例选择（06 §1） |
| 任务状态 | 任务标题旁的状态徽标、阻塞提示、结束时的结果条 | 显示 05 §6.2 的全部任务状态；阻塞时给出原因、已完成内容、需要谁做什么（05 §6.4）；结果条明确写「未写入 CAD / 已写入 CAD / 写入结果不明」 |
| 计划与执行 | 执行计划时间线；被取代的旧计划可展开 | 显示 05 §6.5 的全部步骤状态；规范没有步骤级「已取消」，未执行的步骤显示为「未执行（任务已取消 / 计划已修订）」，不改写成别的状态 |
| 取消 | 「取消任务」→ 二次确认 → 「取消请求已提交」→ 快照变为 CANCELLED 后才显示「已取消」 | 有写入正在进行时提示：取消不撤销已发生的写入 |
| 重新规划 | 审批时「要求修改方案」；证据缺失 / 人工反馈阻塞时「改写计划」 | 只在 Runtime 声明接受的回应里提供（`BlockedReport.allowedResponses`） |
| 审阅与审批 | 候选卡片（展开图、偏好、质量闸门、区域表、来源与哈希、决策记录）+ 审批卡片 | 审批前展示候选哈希、基础版本、绑定范围、执行工具、闸门标准集、策略版本、有效期、一次性；批准需要二次确认；提交后显示「等待 Runtime 写入审批记录」，直到快照确认 |
| 工具执行与诊断 | 每个步骤的「详情」；「高级诊断」默认收起 | 工具 ID / 版本、权限级别、副作用、确定性、尝试次数与错误码、输入输出哈希、是否经对账；预算、版本、事件日志与哈希链 |

加载、空状态、连接错误（含重试）、任务加载错误、表单校验、操作提交失败都有对应状态。

## 6. 与规范的对应

| 规则 | 界面做法 |
|---|---|
| I4 审批只来自审批记录 | 审批走独立端口；对话输入框旁注明「对话消息不构成审批」；测试验证在对话里输入「我已批准」不改变任何状态 |
| I5 偏好与质量分开 | 两个并列的框分别展示，没有任何合并分数；注明偏好值不改变闸门结论 |
| I12 / §10.7 质量闸门失败即关闭 | 界面再按逐项结果复核一次：缺少任何一项结果、任何一项不可评价或未评价，都按未通过处理；Runtime 报「通过」但逐项结果不支持时，显示不一致警告并按未通过处理。未通过的候选只显示诊断与区域提示，不画候选几何，不出现审批入口 |
| 01 §5 规则 3 | AMBIGUOUS / UNMATCHED 区域只给区域提示，不画逐点位移（即使数据里带了位移也不画） |
| §10.2 批准不等于放行 | 审批卡片与完成结果都写明「最终设计需要你在 CAD 中自行确认」 |
| §10.3 审批绑定基础版本 | 决定请求回传候选哈希与基础版本 ID；版本变化导致审批作废时，在步骤与审批记录中显示原因 |
| §7.3 结果不明先对账 | IN_DOUBT 显示为「结果不明」，即使任务被取消也不隐藏；只提供人工对账回应，没有「重试」按钮 |
| §9.2 叙述部分非权威 | 没有引用证据的 agent 消息标注「未引用证据」 |
| §4 运行模式由部署决定 | 模式只在页头显示；产品界面没有切换模式的控件（切换只存在于原型控制面板） |
| §13 预算不能由模型修改 | 预算耗尽时界面不提供「追加预算」，只能取消 |
| 06 §3 访问挑战不自动求解 | 研究任务遇到 CAPTCHA 时暂停，只提供「继续」（人工在自己浏览器中处理后）或「改写计划」 |

## 7. 模拟场景

| 场景 | 模式 | 演示内容 |
|---|---|---|
| 标准流程 | assist-execute / assist | 通过闸门 → 等待审批 → 条件写入；assist 下只展示建议 |
| 偏好高，但未通过质量闸门 | assist-execute / assist | 偏好 0.86，表面贴合未通过；展示步骤被 Policy Gate 拒绝后改为诊断提示 |
| 依据区域对应不明确 | assist-execute / assist | AMBIGUOUS；结论为「无法可靠判断」 |
| 只读工具超时后重试 | assist-execute / assist | FAILED_NO_EFFECT 后作为新尝试重试 |
| 写入超时，结果不明 | assist-execute | IN_DOUBT → 自动对账无法判断 → 人工确认生效 / 未生效（未生效时重试需要新审批） |
| 审批后设计版本变化 | assist-execute | 执行前核对失败 → 审批作废 → 基于新版本重新生成并重新审批 |
| 证据校验失败 | assist-execute / assist | BLOCKED(missing_evidence) → 必须写明说明才能改写计划 |
| 预算耗尽 | assist-execute / assist | BLOCKED(budget)，界面中只能取消 |
| 公开网页要求人工验证 | offline-research | BLOCKED(human_feedback) → 继续或换来源 |

shadow 模式不提供给牙技师的界面（建议不展示，05 §4），因此原型不模拟它。conflict 与 drift 两种阻塞原因由通用的阻塞提示处理，但没有对应的模拟场景。

## 8. 下一阶段需要的后端接口

以下是接入真实 Runtime 时前端需要的接口。标「待定义」的部分 05 目前没有规定，前端类型只是提议，需要与后端共同确定。

| # | 接口 | 内容 | 依据 / 状态 |
|---|---|---|---|
| B1 | 部署信息 | 运行模式、已注册工具（含级别、副作用）、能力开关、策略与闸门标准集版本、当前用户身份及是否已认证 | 05 §4、§7.1；能力开关**待定义** |
| B2 | 病例列表 | 假名化病例摘要（病例 / 患者假名 ID、牙位、设计对象、当前版本与哈希、采集粒度）；按权限过滤 | 02 §1、§6.5，04 §1.2 |
| B3 | 任务快照 | 事件日志投影：任务状态与阻塞报告、计划（含版本与被取代状态）、步骤与每次尝试、候选、决策记录、审批请求、预算、版本 | 05 §6.1、§9.3、§11；快照结构**待定义** |
| B4 | 事件流 | 按 `seq` 增量读取与订阅（SSE 或 WebSocket），断线后从最后的 `seq` 续读；事件类型枚举 | 05 §5.1；事件类型**待定义** |
| B5 | 创建任务 | `prompt` + 可选 `caseId`；返回初始快照 | 05 §6.2 |
| B6 | 对话消息 | 存为数据，不具有任何权限；消息存放位置 | I11；存放层**待定义** |
| B7 | 取消 | 人工取消；需要规定对进行中有副作用步骤的处理（原型假设：在下一个安全点生效，不打断意图记录与对账之间的写入） | 05 §6.3；进行中写入的语义**待定义** |
| B8 | 审批请求读取 | 待决审批请求的完整范围（候选哈希、基础版本与范围、来源、闸门引用、策略版本、有效期） | 05 §10.3 只定义了审批记录；「审批请求」对象**待定义** |
| B9 | 审批决定 | 经身份验证的独立通道提交批准 / 拒绝，回传候选哈希与基础版本 ID 以防基于过时数据决定；「要求修改」= 拒绝 + 人工反馈，需原子化 | 05 §10.3、I4；「要求修改」**待定义**；审批人与有效期未决（05 §10.3） |
| B10 | 人工回应 | 绑定任务与当前阻塞原因的回应（继续 / 改写计划 / 人工对账已生效 / 未生效），写为 HumanFeedbackRecorded；阻塞报告需列出可接受的回应 | 05 §6.4，06 §3；`allowedResponses` **待定义** |
| B11 | 候选展示载荷 | 区域（S_0 归一化弧长、对应状态）、偏好估计、逐项闸门结果；候选几何只对通过闸门的候选下发 | 05 §10.7，02 §9–§11；几何的展示格式**待定义** |
| B12 | 错误模型 | 请求级错误码（不可用、未认证、无权限、不存在、冲突、无效请求）与步骤级错误码 | 05 §7.3；请求级错误码**待定义** |

当前界面**有意没有提供**、需要先定义后端接口的功能：

- E 级回滚（04 §4：回滚本身是需要审批的 E 级动作）
- 追加预算（05 §6.4 的解除条件之一，但没有定义由谁、经什么通道操作）
- 冲突解决（05 §12：模型不能自行解决；人工解决的通道未定义）
- assist 模式下对已展示建议的采纳 / 拒绝反馈（Verification 记录；03 §3.1 的实际接受率需要它）
- 工作假设、Knowledge Store、密封评估的查看界面（面向研究人员，不在牙技师工作区内）

## 9. 已知限制

- Runtime 完全是模拟的；任务描述不影响结果，结果由所选场景决定。
- 没有三维视图。margin line 以「展开图」显示（横轴为 S_0 归一化弧长，纵轴为横向位移），数据是合成的。
- 没有持久化；刷新页面会清空模拟任务。
- 模拟身份未经认证；在模拟部署中允许审批，但标明「审批无实际效力」。非模拟部署下未认证身份不能审批。
- 界面文案为中文，没有引入国际化框架。
- 只做了基本的语义与键盘可达性（标题、区域标签、`aria-live`、焦点样式、非颜色的状态图形），没有经过屏幕阅读器的完整审查。
- 类型基于 05 v0.2（PR #3，未合并）。05 修订或合并后需要复核本目录的契约类型。
- 仓库没有 CI；测试和构建需要在本地运行。
