# ADR-0005 · 设计版本是追加式的版本图；CAD 适配器同时是采集适配器

- 状态：已采纳（2026-10-27）
- 相关：02 数据规范，`packages/data/src/model.ts`、`memoryStore.ts`，`packages/runtime/src/simulation/syntheticCad.ts`

## 背景

02 要求以下几项能够关联起来：动作、中间版本、Correction Episode、区域级几何差异和最终状态。研究层比较的是「AI 初始设计 S_0 → 最终确认版本」的变化，所以必须能区分三件事：

- 谁改的；
- 为什么能改，Copilot 的改动对应哪个审批；
- 改了什么。

撤销和并发编辑也不能抹掉历史。

## 决定

1. **设计版本**：
   - 每个病例的设计版本组成追加式的图，第一个版本是 S_0（`ai_initial`）。
   - 每个新版本带父版本与来源：`technician_edit`、`undo`（带 `revertsTo`）、`copilot_execution`（带 `taskId` 与 `approvalId`）、`import`。
   - 版本不修改、不删除；撤销是一个新版本。
2. **写入约束由数据层强制**：
   - 版本图必须合法（`INVALID_GRAPH`）；
   - Copilot 写入的版本和操作必须带审批 ID（`MISSING_APPROVAL`）；
   - 对应状态不是 MATCHED 的区域，不记录逐点位移。
3. **最终确认**：只能由负责牙技师作出（`OutcomeRecord.geometryConfirmed`）。Final GD 的两端是 S_0 与确认版本（02），应由几何引擎计算。目前还没有几何引擎，合成数据集中的 Final GD 由生成器给出（扩展点 X7）。
4. **采集**：
   - CAD 适配器同时是采集适配器：CAD 侧发生的变化，由它按实际采集粒度（C0–C3）写入数据层。
   - 合成 CAD 就是这样做的：牙技师的并发编辑记为该牙技师的版本；Copilot 的条件写入记为带审批的 Copilot 版本。
5. **结果不明的写入**：版本查询可以对账。写入是否生效，以数据层和 CAD 的版本为准，不以工具的回复为准。

## 后果

- 每个设计版本都能追溯到人或审批。病例记录面板直接展示这张图（来源、审批、任务、哈希、是否已确认）。
- 并发编辑、执行前核对与条件写入共用同一个版本概念，基础版本变化可以被检测到。
- 采集粒度取决于真实 CAD 的能力。C0 / C1 时只有最终状态或少量中间版本，图会退化为很短的链，研究层要按实际粒度解释。

## 何时重新审视

- 真实 CAD 审计显示无法获得 S_0 或中间版本时（PR #3 的 Q18、PR #4 的 Q13）；
- 持久化（X5）选定存储方式时。
