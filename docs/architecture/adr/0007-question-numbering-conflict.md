# ADR-0007 · PR #3 与 PR #4 的 Q13–Q18 编号冲突：只记录，本轮不重新编号

- 状态：记录（2026-10-27）。本轮不处理。
- 相关：`docs/open-questions.md`（`main` 上只有 Q1–Q12）

## 背景

两个未合并的 PR 都在 `docs/open-questions.md` 中从 Q13 开始新增问题，同一编号的含义不同：

| 编号 | PR #3（`claude/sharp-hawking-4p3e5y`） | PR #4（`claude/record-3shape-sample-size`） |
|---|---|---|
| Q13 | H1 主要终点是否改为「修正意图」 | 3Shape 能导出什么（S_0、S_final、中间版本、操作日志、格式与权限） |
| Q14 | Runtime 部署位置 | 总计 ≤ 5 个病例时研究范围如何调整（PR #4 中已决定：标准病例设计） |
| Q15 | 是否使用外部模型 API，允许外发哪些数据类别 | 标准病例来源与授权 |
| Q16 | 数据保留与删除政策 | 每位牙技师能否参与 K + 1 个会话（含重复会话） |
| Q17 | E 级审批由谁授予、有效期多长 | 解剖分区如何在 S_0 上划分 |
| Q18 | 已有 STL 包含哪些版本 | 独立复核专家从哪里来 |
| Q19 | 患者假名映射的保管人与撤回渠道 | — |

PR #4 的 Q14–Q16、Q18 依赖标准病例设计，这又与 [ADR-0003](0003-one-technician-per-case.md) 的约束冲突。

## 决定

- 本轮不重新编号，也不展开研究问题的全面审查。
- 本仓库的代码与架构文档不单独引用 Q13 及以后的编号。确需引用时写明出处，例如「PR #3 的 Q17」。

## 后果

两个 PR 合并时必须先解决编号冲突，否则引用会指向错误的问题。负责合并的人需要统一重新编号，并更新所有引用。

## 何时重新审视

PR #3 或 PR #4 准备合并时。
