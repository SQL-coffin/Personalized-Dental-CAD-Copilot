## 1. 患者数据保护

### 1.1 术语

| 术语 | 含义 | 能否按患者追溯 | 本项目中的用法 |
|---|---|---|---|
| 去标识化 | 去除姓名、病历号、联系方式、订单号等直接标识符 | 取决于是否保留映射 | 数据进入 Evidence Store 之前必须完成 |
| 假名化 | 去标识化之后，以研究用的假名 ID 代替标识符；映射表另行保管 | 能，但只能经映射表保管方 | 本项目的默认做法；假名化数据仍按个人数据管理 |
| 不可逆匿名化 | 即使结合其他信息，也无法再识别到个人 | 不能 | 只可能适用于满足汇总条件的统计结果；是否成立按适用法规判断（Q5） |

如果采用不可逆匿名化，就无法保证按患者找全并删除其记录，也无法按患者划分数据。因此本项目的病例级数据采用假名化，而不是不可逆匿名化。

### 1.2 本项目的做法

- 数据进入 Evidence Store 之前去除直接标识符，以**患者假名 ID** 和**病例假名 ID** 代替。
- 患者假名 ID 在同一患者的所有病例、牙位、重复扫描和修复体版本中保持一致，用于按患者划分数据（03 §2）和记忆查询中的患者排除（05 §8.3）。
- 映射表由数据提供方或独立的数据托管人保管；Runtime、Research Engine 和研究人员都不能访问（Q19）。按患者的撤回或删除请求，由保管方转换为患者假名 ID 后提交（05 §10.5）。
- 扫描网格本身可能具有可识别性，因此即使去除了直接标识符，也不视为匿名数据：按患者密钥加密存储；只在 Runtime 内部由适配器和 Geometry Engine 读取；默认不外发（05 §10.6）；只在经授权的界面中向人展示。
- 默认把所有病例级数据（网格、曲线、GD 描述符、逐病例预测）当作假名化的个人数据管理。只有满足登记的汇总条件（例如最小分组规模）、且不含病例级几何的统计结果，才可能被认定为不可逆匿名化数据。
- 适用的法规与合作方协议待确认（取决于数据来源地区，Q5、Q10）。

## 2. 操作权限

- 预测/推理层只能提出候选修改，不能直接写入最终几何。
- 所有写操作经 Runtime Harness 的工具注册与参数校验。
- 权限分级：

| 级别 | 允许的动作 | 示例 | 要求 |
|---|---|---|---|
| R · 只读 | 读取病例、几何版本、日志；计算 GD、对应关系、检查结果 | 计算修改前后差异，检索相似病例 | 记录访问日志 |
| S · 建议 | 生成候选修改及决策记录，不改变设计 | 提示「远中颊侧可能需要降低」 | 必须附 Preference、Quality、对应状态；只有通过质量闸门的候选才能以可采纳的形式展示（05 §10.7） |
| E · 确认后执行 | 把已批准的候选写入 CAD 设计 | 按建议调整 margin line 某段 | 牙技师逐次批准；执行前保存版本并核对基础版本（05 §10.3）；可一步回滚 |

- S 级展示建议不改变设计，不需要审批；E 级执行需要对该候选的逐次批准（05 §10.2）。
- 没有任何动作可以不经批准直接改变设计；也没有动作可以确认或放行最终设计。
- 审计：每次 S、E 级动作记录输入版本、工具调用、参数、结果、批准人和时间，能够在 Evaluation Harness 中完整重放。

## 3. 人工审批

- 展示建议（S 级）不改变设计，不需要审批；但只有通过质量闸门的候选才能以可采纳的形式展示（05 §10.7）。
- 执行候选（E 级）需要牙技师对该候选的逐次明确批准；批准绑定候选及其基础设计版本，基础版本变化即作废（05 §10.3）。
- 执行批准不等于放行最终设计。最终设计由牙技师在 CAD 中自行确认，系统不做最终放行。
- 批准、拒绝及其理由都记录为 Evidence。

## 4. 撤销机制

- 每次执行前保存不可变版本，支持一步回滚到执行前状态。
- 回滚本身作为事件记录，用于后续分析。

## 5. 错误建议处理

- 被拒绝的建议单独存档，相似情境下抑制重复推荐。
- 证据不足时输出「无法可靠判断」，而不是给出低质量建议。
- 定期在 Evaluation Harness 中回放被拒绝和被回滚的案例，进行失败分析。

## 6. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| CAD 软件不暴露几何状态 | 修改前后状态不可信，标签失效 | 阶段 1 先验证可观测性；不满足即停止 |
| 单个牙技师样本量过小 | H3 无法得出统计结论 | 预先估计样本需求，必要时调整研究范围 |
| 个人偏好与设计质量混淆 | 系统精确复现不适合当前病例的习惯 | Preference 与 Quality 分开评价；Quality 作为推荐闸门 |
| 曲线对应错配 | 位移标签错误，模型学到虚假的修改 | MATCHED / AMBIGUOUS / UNMATCHED 状态；只有 MATCHED 进入位移分析 |
| 把「被保留」当作「正确」 | 训练标签混入未经验证的修改 | GD 与 Validated Improvement 分开；质量结论只用有独立证据的记录 |
| 数据泄漏（同一患者的多个牙位、重复扫描或修复体版本跨越训练和测试） | 高估泛化能力 | 按患者划分；需要一致的患者假名 ID |
| 把采样点或区域当作独立样本 | 虚高的统计把握度 | 分析单位为病例或患者，统计考虑层级结构 |
| 法向位移被误读为离面错误 | 错误地判定几何质量 | 位移分解与表面贴合检查分开 |
| 上下文压缩或恢复导致审批、未完成任务或证据丢失 | 越权执行或遗漏步骤 | 上下文只是缓存；审批只来自审批存储；恢复协议（05 §9） |
| 数据内容中的文字被当作指令（提示注入） | 任务或权限被改变 | 数据内容不是指令；Policy Gate 为确定性代码（05 §2、§10.1） |
| 患者数据经外部模型 API 外发 | 违反数据保护要求 | 外发控制（05 §10.6）；待 Q14、Q15 |
| 证据只追加与同意撤回、保留期限冲突 | 无法履行删除义务 | 按患者加密、受控删除与 lineage（05 §10.5）；待 Q16 |
| 研究过程读取留出评估数据 | 评估结果虚高 | 数据分区隔离（05 §10.4） |
| 评估结果经日志、工具返回值或重复查询回流到研究过程 | 留出集间接泄漏，评估结果虚高 | 密封评估通道；运行次数上限与留出集消耗规则（05 §10.8） |
| 崩溃或超时后重复执行写入 CAD 的动作 | 设计被重复修改 | 意图记录与对账；结果不明时先对账，不重试（05 §7.3、§9.4） |
| 基于旧设计版本的候选被写入已更新的设计 | 设计被错误修改 | 审批绑定基础版本，执行前核对，条件写入或写后对账（05 §10.3） |
| 只写删除墓碑，副本、备份、索引或派生数据仍可读 | 删除义务没有真正履行 | 删除层次表与恢复演练（05 §10.5） |
