# ADR-0006 · Agent 只经 AgentSession 行事；模型输出不具权威；候选只来自候选来源工具

- 状态：已采纳（2026-10-27）
- 相关：05 §6–§11（PR #3），`packages/agent-tools/src/agent/agent.ts`，`packages/agent-tools/src/tools`，`packages/runtime/src/engine`

## 背景

05 的核心不变量：

- 对话不是审批（I4）；
- 偏好与质量分开（I5）；
- 数据不是指令（I11）；
- 质量闸门失败即关闭（I12）。

如果 agent 能直接调用工具、改状态，或用叙述文字产生候选，这些不变量就只能靠约定维持。将来换成真实模型时，agent 是最不可信的部分。

## 决定

1. **Agent 的权限**：agent 只拿到 `AgentSession`。它能做的事是：
   - 写计划，请求执行计划；
   - 发叙述；
   - 读取已登记候选的信息；
   - 记录决策草稿；
   - 请求人工反馈；
   - 提出完成，是否允许由状态机决定。

   它看不到 engine、工具实现、数据存储或 CAD。
2. **工具的执行**：
   - `StepExecutor` 是唯一调用工具的代码。
   - 每个工具都在目录中声明级别（R / S / E）、角色、允许的模式、数据范围、外发类别与超时。
   - 按运行模式注册：shadow 模式不注册展示工具；写入工具只在 assist-execute 模式注册；研究工具只在 offline-research 模式注册。
3. **Policy Gate 是确定性代码**，负责计划预检、步骤检查、外发检查、审批核对与基础版本核对。规则按工具角色执行：
   - 展示步骤只有在候选通过质量闸门时，才能以可采纳形式展示；
   - 未通过的候选只能作为去掉几何与位移的诊断提示；
   - 写入步骤不会为不可采纳的候选请求审批。
4. **候选**：
   - 只能来自 `candidate_source` 角色的工具（当前是冻结版本的个人检索 Predictor），由 `TaskRun` 登记哈希。
   - 偏好估计与闸门结果并列保存，不合成一个分数；`isGatePassed` 缺少任何一项结果都判为未通过。
5. **模型调用**：每次调用都按 05 §7.4 记录（`ModelCallRecorded`）。模型输出只作为叙述，没有引用证据的叙述在界面上标注「未引用证据」。

## 后果

- 脚本 agent 换成真实模型驱动的 agent 时，权限不会扩大：它仍然只能经 `AgentSession` 提出请求，由 engine 和 Policy Gate 决定。
- 规则集中在 engine 中，可以单独测试。
- agent 能力受 `AgentSession` 接口限制。新增能力，例如追加预算或冲突解决，需要先扩展接口并定义对应的人工通道（扩展点 X11、X12）。

## 何时重新审视

- 接入真实模型（X4）时；
- 05 的不变量修订或合并时。
