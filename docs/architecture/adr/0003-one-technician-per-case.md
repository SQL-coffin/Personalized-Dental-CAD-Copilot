# ADR-0003 · 每个病例只分配给一位牙技师；数据结构分开记录病例差异与牙技师差异

- 状态：已采纳（2026-10-27，项目负责人给出的实验设计约束）。每位牙技师的病例数：**待确认**。
- 相关：`packages/data`（`model.ts`、`memoryStore.ts`、`synthetic.ts`），`packages/research`（`design.ts`、`registration.ts`），扩展点 R1、R2

## 背景

项目负责人给出的实验设计约束：

- 每个病例只分配给一位牙技师；
- 不同牙技师不会处理同一个病例；
- 同一位牙技师不会重复处理同一个病例；
- 不再默认采用重复病例分配或拉丁方设计；
- 每位牙技师的病例数量仍需确认，不能自行设定为最终方案；
- 数据结构必须能区分病例差异、牙技师差异、操作事件、设计版本和几何变化，不能把病例之间的差异直接解释为个人偏好。

未合并的 PR #4（「采用标准病例设计，新增 H0 个人差异存在性」）采用了相反的设计：每位牙技师修正同一组标准病例，并安排间隔 ≥ 2 周的重复会话。

## 决定

1. **分配**：
   - `CaseAssignment { caseId, technicianId, assignedAt, ruleVersion }`，规则版本为 `assign-one-technician-per-case-v1`。
   - 数据层拒绝第二次分配（`ASSIGNMENT_CONFLICT`）。
   - 只有负责牙技师能开会话、编辑、撤销和确认（`NOT_ASSIGNED_TECHNICIAN`）。
   - Runtime 只列出、只接受分配给登录者的病例（`FORBIDDEN`）。
2. **五类信息分开记录**：

   | 信息 | 记录 |
   |---|---|
   | 病例差异 | `CaseCovariates`：修复体、牙位、牙弓、牙类、预备体类型、扫描质量 |
   | 牙技师差异 | 分配记录与牙技师（假名） |
   | 操作事件 | `EditAction`：执行者（牙技师或 Copilot）、工具、采集粒度、区域 |
   | 设计版本 | 追加式版本图，见 [ADR-0005](0005-append-only-version-graph.md) |
   | 几何变化 | `GeometryDelta`：step / episode / final 三类，按区域记录对应状态与位移 |

3. **分析**：
   - 牙技师与病例是嵌套关系。两位牙技师之间的差异，同时也是两组病例之间的差异。
   - `diagnoseDesign` 逐项标明哪些分析可做、哪些混杂、哪些不存在：
     - 同一病例的跨人比较、个人内重复一致性：不存在。
     - M vs P_self：只在本人历史内比较，可做。
     - M vs G 及牙技师之间的修正量比较：混杂，需要按病例协变量调整或检查平衡，并报告协变量构成的不平衡。
   - 登记草案中 H3 标为 `limited_by_design`。
   - 病例记录面板写明「病例之间的差异不等于个人偏好」。
4. **病例数**：
   - 不设定。登记草案与设计诊断都是 `casesPerTechnician: 'to_be_confirmed'`。
   - 合成数据集中每人 6 个历史病例只是演示参数（`historicalCasesPerTechnician`），生成假设在界面中可见。

## 后果

- 结构上无法把病例差异记成个人偏好：比较总是带着病例协变量，跨人比较被标为混杂。
- 「个人差异是否存在」不能再用同一病例的跨人比较来检验；个人内一致性也无法估计。PR #4 的 H0 及其依赖的病例池、重复会话、复核专家安排，需要项目负责人按新约束重新确定。本轮不修改研究设计文档（00、03 与 PR #4）。
- 按协变量调整的效力取决于病例数与病例构成，所以每人病例数的确认会直接影响 H2、H3 的可行性。

## 何时重新审视

- 每位牙技师的病例数确认之后；
- 03 实验协议按本约束修订时；
- PR #4 的处理有结论时。
